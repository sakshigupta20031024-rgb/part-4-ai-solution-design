# part-4-ai-solution-design

### Business Domain
Finance

# Task 2: Define the Business Problem

What problem is being solved?

Suspicious Transaction Detection:The problem is detecting suspicious financial transactions that may indicate fraud, money laundering, or unauthorized account activity.

Who are the users or stakeholders?

-Banks and financial institutions
- Fraud investigation teams
- Customers
- Compliance and risk departments

What is the current manual or traditional process?

Currently, suspicious transactions are identified using:
- Rule-based systems
- Manual review by fraud analysts
- Threshold-based alerts
For example:
- Large transactions above a fixed amount
- Multiple transactions within a short time

What are the limitations of the current process?

- Too many false alerts
- Fraud patterns change frequently
- Manual checking takes time
- Difficult to detect complex fraud behavior
- Genuine users may get blocked incorrectly

### Selected AI Task Type:
Anomaly Detection / Classification

This problem uses anomaly detection/classification because AI can learn normal customer transaction behavior and automatically identify unusual or fraudulent transactions.

## Task 4 — Data Requirement Plan

## Type of data needed

- Transaction history
- Customer account activity and details
- Device information
- Transaction timestamps

## Structured or unstructured data

Mostly structured data.

## Input features

Examples:
- Transaction amount
- Transaction time
- Customer location
- Device ID
- Transaction frequency

## Target variable / labels

- Fraud = 1
- Normal transaction = 0

## Data collection method

Data can be collected from:
- Banking transaction systems
- Payment gateways
- Mobile banking applications(ex: Gpay, Phonepay, Paytm, etc)

## Data quality risks

- Missing values
- Duplicate transactions
- Incorrect labels
- Imbalanced fraud data
- Outdated transaction patterns

# Task 5 — Model Recommendation

## Recommended Model:
Feed-forward Neural Network / Autoencoder
An autoencoder neural network is suitable because it learns normal transaction behavior and automatically detects unusual or suspicious transactions that may indicate fraud

# Task 6 — Evaluation Plan

## Technical metrics

- Precision
- Recall
- F1-score
- ROC-AUC

## Business metrics

- Reduction in fraud losses
- manual_processing_hours
- average_resolution_time_hours
- error_rate_percent	
- customer_satisfaction_score	
- monthly_cases 

## Possible failure cases

- Genuine transactions flagged as fraud
- New fraud patterns not detected
- Incomplete data

## Human review process

Suspicious transactions should still be reviewed by fraud analysts before blocking accounts permanently.

AI should support human decision-making, not fully replace it.

# Task 7 — Responsible AI Considerations

If training data is biased, the system may unfairly flag certain customers.

False positives may block genuine customers and may create disbelief im customers.

Financial transaction data contains sensitive personal information.Strong security and encryption are necessary.

Banks should not depend entirely on AI systems without human monitoring.

Incorrect fraud alerts may affect customer trust and banking experience.

Human fraud analysts should review high-risk alerts generated by the AI model.
